# EcoPulse — Threat Model

**Standard:** OWASP Top 10 (2021)
**Last updated:** 2026-06-12

## A01 — Broken Access Control

**Risk:** User A reads User B's carbon data.

**Mitigations:**
- All Firestore queries include `.where("user_id", "==", uid)` — enforced in every route handler
- ADK agent Firestore tools are parameterized by uid; the parameter is set by the gateway, never from user input
- Cross-user scoped-tool tests in `services/agents/tests/test_scoping.py` verify isolation

---

## A02 — Cryptographic Failures

**Risk:** Sensitive user data (activity logs, location from photos) exposed in transit or at rest.

**Mitigations:**
- All traffic: HTTPS enforced via Cloud Run (TLS 1.3)
- HSTS header set with 2-year max-age
- EXIF stripped from images before storage (GPS coordinates removed)
- Signed Cloud Storage URLs with 15-minute expiry — never expose raw GCS URLs to clients
- All secrets in Google Secret Manager — never in code, env files, or GitHub Secrets

---

## A03 — Injection

**Risk:** Hostile text embedded in a photographed image manipulates Gemini agent behavior (prompt injection).

**Mitigations:**
- All user content wrapped in XML delimiters in every system prompt:
  ```
  <user_content>
  {user_input}
  </user_content>
  ```
- Instruction hierarchy: system prompt establishes role, user content cannot override it
- Output validation: all agent responses validated against Pydantic schemas before use
- Injection test cases in `services/agents/tests/test_injection.py`

---

## A04 — Insecure Design

**Risk:** LLM-generated CO₂e numbers are incorrect and mislead users into wrong decisions.

**Mitigations:**
- LLM never does arithmetic: all CO₂e math is deterministic Python (emissions engine)
- Every displayed number traces to a specific DEFRA/EPA emission factor
- Swap suggestion savings percentages are calculated by the engine, never generated by the LLM

---

## A05 — Security Misconfiguration

**Risk:** Cloud Run services publicly accessible, secrets hardcoded.

**Mitigations:**
- Only `ecopulse-frontend` has `--allow-unauthenticated`; all other services require auth
- Zero secrets in code — gitleaks CI gate blocks any commit containing credentials
- Dependabot enabled for automated dependency updates
- `.pre-commit-config.yaml` runs gitleaks on every commit

---

## A06 — Vulnerable and Outdated Components

**Mitigations:**
- Dependabot configured for both npm and pip
- `npm audit` and `pip-audit` in CI
- Distroless base images minimize installed packages

---

## A07 — Identification and Authentication Failures

**Risk:** Unauthenticated access to user data.

**Mitigations:**
- Firebase Auth ID token required on every protected API route
- Token verified server-side via Firebase Admin SDK (not client-side)
- Rate limiting at gateway: 60 req/min per IP

---

## A08 — Software and Data Integrity Failures

**Risk:** Malicious dependency injected via supply chain.

**Mitigations:**
- `package-lock.json` and `requirements.txt` with pinned versions committed
- Dependabot monitors for vulnerable versions
- gitleaks prevents accidental secret leaks in dependencies

---

## A09 — Security Logging and Monitoring Failures

**Mitigations:**
- Cloud Run structured logging to Cloud Logging
- Auth failures logged with IP (for rate-limiting analysis)
- Agent output validation failures logged as WARNING

---

## A10 — Server-Side Request Forgery (SSRF)

**Risk:** Agent Firestore tools manipulated to access internal GCP metadata endpoints.

**Mitigations:**
- Firestore tools accept only `uid` parameter (controlled by gateway)
- No agent tool accepts arbitrary URLs
- Cloud Run metadata endpoint blocked by VPC configuration
