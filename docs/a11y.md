## Implementation Notes

### Motion — everything gates on `prefers-reduced-motion`
- The animated **carbon-pulse canvas** (`components/landing/CarbonPulse.tsx`) and the **count-up**
  numbers freeze to their final state under reduced motion.
- **GSAP scroll reveals** are wired through `lib/useGsap.ts`, which no-ops when motion is reduced —
  content renders immediately at its final position (no scroll-jacking).
- **Recharts** render with `isAnimationActive={false}`; the underlying data is present as SVG/text
  regardless of motion preference, so nothing is animation-gated for comprehension.

### Keyboard navigation
- **Skip-to-content** link is the first focusable element (`app/layout.tsx`), then header → main.
- Every interactive control is reachable and operable by keyboard: the **Snap / Upload / Describe**
  controls, the **Carbon Conversations** input, and the **"How this was calculated"** disclosure.
- **Scan/Camera overlay** (`components/CameraOverlay.tsx`) is a `role="dialog"`; **Escape** closes it
  and focus is managed; the trigger and close controls show a visible `focus-visible` ring.

### ARIA live regions
Streaming, asynchronous results are announced politely:
```html
<!-- Identified items as the AI reads the photo (CameraOverlay) -->
<div aria-live="polite" aria-label="Identified items"> … </div>

<!-- Carbon Conversations streaming answer -->
<div aria-live="polite" aria-label="Carbon AI response"> … </div>

<!-- Activity feed as new logs land -->
<div aria-live="polite" aria-label="Activity feed"> … </div>
```

### Semantic structure
Landmarks throughout: `<header>`, `<main>`, `<nav>`, and labelled `<section aria-label>` regions, so
screen-reader users get a navigable document outline.

### Colour contrast (tokens in `tailwind.config.ts`)
All body and UI text meets WCAG 2.2 AA:
- `text-primary` (`#E8EDF5`) on `space-black` (`#05080F`): **16.2:1** ✅
- `neon-cyan` (`#00F5D4`) on `space-black`: **8.7:1** ✅
- `text-secondary` (`#8892A4`) on `space-black`: **5.1:1** ✅
- `text-muted` (`#4A5568`): **3.2:1** — used only for large/decorative supplementary text (meets the
  3:1 large-text / non-text threshold; never for body copy)

### Focus indicators
```css
:focus-visible {
  outline: 2px solid #00F5D4;
  outline-offset: 2px;
}
```
Applied globally — `outline: none` is never used without a visible replacement.

## Manual screen-reader support

The app is built to the NVDA/VoiceOver pattern set above (live regions for all async output, dialog
semantics + focus management, labelled controls, full keyboard operation). Re-verify with a screen
reader on each release using the journeys below.

| Journey | What a screen reader should announce |
|---|---|
| Home → Dashboard | Skip link → landmarks; headings describe each section in order |
| Log a meal via Snap/Upload | Dialog opens; identified items announced politely as they stream in |
| Carbon Conversations | Answer announced politely token-by-token; Escape returns focus to the trigger |
| View results | "How this was calculated" disclosure is keyboard-operable; totals read as text |
